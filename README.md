# 大规模 GPU Kubernetes 训练集群运维学习路径

本文件是全书写作大纲与验收标准；章节正文位于 `docs/chapters/`。本地预览：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdocs serve
```

## 定位与学习目标

本学习路径面向已有 Linux、容器和 Kubernetes 基础，准备承担 AI Infra、GPU 集群或 HPC 平台生产运维工作的工程师。招聘要求中的“5 年以上 Linux/Kubernetes/HPC 或智算基础设施经验、3 年以上生产 Kubernetes 运维经验”属于岗位经历门槛，课程不能替代这些生产经验；课程负责系统补齐岗位知识、实践方法和故障处理框架。

完成学习后，读者应能：

- 说明 GPU 服务器从硬件验收到 Kubernetes 资源池的生命周期及各层责任边界。
- 运维 NVIDIA GPU 软件栈和 Kubernetes 组件，并能从指标、日志和拓扑信息定位常见故障。
- 验收 IB/RoCE 训练网络、共享存储和多节点训练环境，能与网络、存储及供应商团队协同排障。
- 处理调度失败、NCCL 超时、训练挂起、GPU 掉卡和性能退化等生产问题。
- 将巡检、变更、恢复和退役流程沉淀为可审计、可回滚的自动化 SOP。

学习路径按“服务器与操作系统 -> Kubernetes 与容器 -> GPU 资源 -> 网络、通信与存储 -> 调度和故障处理 -> 自动化与生产保障”递进。建议用隔离的实验环境完成实践；涉及驱动、固件、交换机、生产节点或集群级变更的内容，只在获批的维护窗口和变更流程内执行。

### 学习阶段与实践环境

| 阶段 | 章节 | 阶段验收 |
| --- | --- | --- |
| 基础设施与容器 | 第 1-4 章 | 能解释服务器到 Pod 的资源链路，并完成 Kubernetes/容器基础巡检 |
| GPU 资源管理 | 第 5-6 章 | 能完成 GPU 节点健康检查、资源注册链路说明和入池验收设计 |
| 训练依赖 | 第 7-9 章 | 能交付网络、分布式通信和存储的验收步骤与基线记录 |
| 调度与故障诊断 | 第 10-11 章 | 能分析排队/资源碎片，并按证据闭环处理跨层故障案例 |
| 生产运营与综合演练 | 第 12-14 章 | 能交付自动化巡检、变更方案和端到端演练复盘 |

实验条件按能力逐级扩展：无 GPU 的本地容器/Kubernetes 环境用于基础对象和排障流程；单 GPU 节点用于驱动、容器和 DCGM 实践；真实多节点 GPU、IB/RoCE 和共享存储环境用于网络及分布式训练验收。模拟环境可以练习流程，不能证明真实 RDMA、GPU 拓扑或存储性能。

## 章节大纲

### 第 1 章：岗位能力地图与学习路径

- **学习目标：** 理解岗位的职责边界、主要依赖团队、核心故障域和能力成长顺序。
- **内容大纲：** GPU 集群分层架构；从服务器、网络、存储到 Kubernetes 工作负载的资源链路；平台运维、训练框架、网络和硬件团队的职责边界；故障影响面与优先级；学习路线和实验室分级。
- **实践与产出：** 绘制一张 GPU 训练平台依赖图，并制作个人技能差距清单。
- **章末面试题：** 8-10 题；覆盖岗位职责拆解、故障域判断、跨团队边界和学习/排障优先级。

### 第 2 章：Linux、硬件与 GPU 服务器基础

- **学习目标：** 能检查服务器健康状态，理解 CPU、内存、PCIe、NUMA、GPU 和网卡的拓扑关系。
- **内容大纲：** Linux 启动与 systemd；进程、内存、文件系统、日志、时间同步和内核模块；NUMA/CPU 亲和性；PCIe 链路、IOMMU、BAR 和 GPU/NIC 拓扑；BMC、固件、传感器、磁盘与网卡基础；服务器上架、验收和故障隔离流程。
- **实践与产出：** 编制 GPU 服务器入池验收清单，采集并解读一台节点的拓扑和健康信息。
- **章末面试题：** 8-12 题；覆盖 NUMA/PCIe 拓扑、节点启动异常、内核日志、硬件验收和隔离决策。

### 第 3 章：Kubernetes 生产集群运维

- **学习目标：** 理解控制面和节点关键组件，能沿 Kubernetes 控制链路排查资源无法运行的问题。
- **内容大纲：** API Server、etcd、Scheduler、Controller Manager、kubelet 的作用和依赖；对象状态与调度流程；节点加入、cordon/drain 和 NotReady 排查；CNI、CSI、CoreDNS；证书与时间同步；集群升级、兼容性检查和回滚。
- **实践与产出：** 编写控制面、节点、DNS、CNI/CSI 和证书的只读巡检清单，并演练一个隔离环境中的节点故障排查。
- **章末面试题：** 8-12 题；覆盖控制面不可用、Pod Pending、节点 NotReady、DNS/网络异常、证书和升级回滚。

### 第 4 章：容器运行时与 GPU 容器环境

- **学习目标：** 能解释 GPU 设备如何从宿主机暴露到容器，并定位镜像、运行时和版本兼容问题。
- **内容大纲：** containerd、CRI、OCI、runc 与 RuntimeClass；NVIDIA Container Toolkit 和设备注入；设备文件、驱动库挂载、权限与安全边界；镜像分层、拉取和缓存；宿主机 Driver 与容器 CUDA/cuDNN/NCCL 兼容关系；Pod 内 GPU 可见性检查。
- **实践与产出：** 制作容器 GPU 环境自检流程，覆盖宿主机、运行时、Pod 和框架四层。
- **章末面试题：** 8-12 题；覆盖容器看不到 GPU、驱动库挂载失败、版本不兼容、权限问题和镜像设计。

### 第 5 章：NVIDIA GPU 软件栈与硬件故障定位

- **学习目标：** 能从 GPU 指标、事件和系统日志区分软硬件故障，并选择安全的恢复或隔离动作。
- **内容大纲：** NVIDIA Driver、CUDA、NVML、DCGM 的关系；nvidia-smi 与 DCGM 指标；Xid、ECC、温度、功耗、时钟、显存和 PCIe 错误；GPU Reset 与节点重启的边界；MIG 基础及其适用场景；驱动安装、升级、回滚和版本矩阵。
- **实践与产出：** 建立 GPU 健康检查与故障分级 runbook，列出升级前后验证项和升级失败回滚条件。
- **章末面试题：** 8-12 题；覆盖 Xid/ECC 诊断、掉卡、健康检查、性能退化、驱动升级和 GPU 隔离。

### 第 6 章：Kubernetes GPU 资源管理

- **学习目标：** 理解 GPU 资源发现、注册、调度分配和容器内可用性的完整链路。
- **内容大纲：** Device Plugin 工作机制；GPU Operator 的组件和生命周期管理；GPU Feature Discovery 与节点标签；整卡分配、MIG 资源暴露和共享方式；拓扑管理与 NUMA 亲和性；资源申请、限制、可见性和回收；DRA 等新接口的定位与版本状态核验。
- **实践与产出：** 绘制“物理 GPU -> 节点资源 -> Pod 分配 -> 容器设备”的状态链路，并设计一份 GPU 节点入池验收测试。
- **章末面试题：** 8-12 题；覆盖 Device Plugin、GPU Operator、资源注册失败、MIG/拓扑标签及新接口选型。

### 第 7 章：IB/RoCE 训练网络与 RDMA

- **学习目标：** 能读懂训练网络拓扑，参与网络验收，并把链路、拥塞和配置问题与训练症状关联起来。
- **内容大纲：** InfiniBand 与 RoCEv2 的架构差异；RDMA 基本路径；HCA、端口、交换机和 GPU Direct RDMA 概念；MTU、GID、路由、QoS；PFC 与 ECN 的作用和配置风险；无损网络与拥塞控制；网络团队协作接口、验收指标和变更边界。
- **实践与产出：** 选择实验环境可用的 IB 或 RoCE 完成验收；形成包含连通性、带宽/延迟基线、错误计数器、MTU/GID 和拓扑记录的清单，并能解释另一种网络的关键差异。
- **章末面试题：** 8-12 题；覆盖 IB/RoCE 选择、RDMA 链路、PFC/ECN、MTU/GID、网络验收和跨团队定位。

### 第 8 章：NCCL、MPI 与多节点训练通信

- **学习目标：** 能理解常见集合通信，并按 rank、进程、GPU、NIC 和网络逐层诊断训练通信故障。
- **内容大纲：** PyTorch Distributed 与 ProcessGroup；MPI 启动和进程映射；NCCL Ring/Tree 与 AllReduce、AllGather、ReduceScatter、AllToAll；节点内 NVLink/NVSwitch 和节点间网络；rank/world size、接口选择、拓扑发现及常见调试信息；通信与计算重叠；NCCL timeout 和 watchdog 的排查边界。
- **实践与产出：** 选用 PyTorch Distributed、MPI 或 NCCL 中至少一种完成多节点通信验收，比较单机与跨机基线，并制作 NCCL timeout 排查决策树；对其余组件说明职责和集成关系。
- **章末面试题：** 8-12 题；覆盖 collective 语义、rank 挂起、NCCL timeout、通信性能异常、拓扑和日志分析。

### 第 9 章：训练存储、缓存与数据管道

- **学习目标：** 能定位训练输入和 checkpoint 路径上的容量、带宽、延迟、元数据和挂载健康问题。
- **内容大纲：** NFS；Ceph 与并行文件系统；对象存储及其访问模式；本地 NVMe 和缓存；CSI/PV/PVC 与容器挂载；训练数据读取、元数据压力、checkpoint 读写和恢复；挂载健康检查、权限、配额和故障域；存储团队验收协作。
- **实践与产出：** 从 NFS、Ceph/并行文件系统、对象存储、高性能缓存中选择至少两类做选型/验收对比，并制作挂载自检清单和数据读取/checkpoint 基准测试方案。
- **章末面试题：** 8-12 题；覆盖 checkpoint 慢、数据加载瓶颈、共享文件系统故障、对象存储接入和缓存命中问题。

### 第 10 章：训练作业调度与 GPU 容量规划

- **学习目标：** 能分析作业排队和资源碎片，设计满足公平性、利用率和训练拓扑要求的调度策略。
- **内容大纲：** Kubernetes 默认调度与训练作业调度差异；Volcano/Kueue 等队列方案的职责和选型；Gang Scheduling；队列、配额、优先级、抢占和公平共享；GPU 拓扑感知；资源碎片与作业排队；利用率指标的局限；容量规划、增长预测和故障余量。
- **实践与产出：** 基于给定工作负载编制队列/配额方案和 GPU 容量规划表，并说明关键取舍。
- **章末面试题：** 8-12 题；覆盖 Gang 调度、排队策略、资源碎片、配额/抢占、公平性和容量规划。

### 第 11 章：分布式训练生产故障诊断

- **学习目标：** 建立可重复的跨层排障方法，优先确定故障范围、影响面和恢复路径。
- **内容大纲：** 统一排障顺序：症状与时间线、影响面、最近变更、指标/日志/事件、拓扑与依赖、假设验证、恢复、复盘；Pod Pending/启动失败；调度失败；NCCL timeout 与挂起；GPU Xid/ECC/掉卡；节点故障；吞吐下降和性能退化；存储抖动；避免无证据重启和扩大故障面。
- **实践与产出：** 完成至少三个故障演练记录，每份包含证据、排除过程、临时恢复、根因、长期措施和升级路径。
- **章末面试题：** 10-15 题；以生产场景为主，要求给出排查顺序、证据来源、止损动作、恢复验证和升级协作方式。

### 第 12 章：可观测性、巡检与运维自动化

- **学习目标：** 能为 GPU 集群建立有效告警和巡检，并将重复 SOP 变成可审计、可回滚的工具。
- **内容大纲：** DCGM Exporter、Prometheus、Grafana 与日志/事件关联；节点、GPU、网络、存储、调度和训练作业的关键指标；告警分级、抑制和去重；Shell/Python/Go/Ansible 的运维适用场景；幂等、并发控制、超时、重试、审计和权限；自动隔离与恢复的护栏。
- **实践与产出：** 选用 Shell、Python、Go 或 Ansible 中至少一种，交付可重复运行的只读巡检工具或任务，提供输入、输出、失败处理和审计说明。
- **章末面试题：** 8-12 题；覆盖指标选择、告警质量、巡检设计、幂等自动化、误操作防护和 SOP 产品化。

### 第 13 章：生产变更、值班与集群生命周期

- **学习目标：** 能安全完成节点纳管、升级、维护、恢复和退役，并在值班与重大任务保障中做好沟通和记录。
- **内容大纲：** 节点上架/入池/隔离/恢复/退役；Kubernetes、GPU Operator、Driver 和固件升级依赖；变更评审、灰度、维护窗口、备份、回滚条件和验收；cordon/drain 与工作负载保护；值班响应、严重度、升级机制、状态沟通、故障复盘；容量风险和供应商协同。
- **实践与产出：** 编写一次 GPU 节点驱动升级变更单，包含影响分析、前置检查、灰度、验证、回滚和沟通模板。
- **章末面试题：** 8-12 题；覆盖节点 drain、驱动/集群升级、回滚触发、重大任务保障、事故沟通和供应商协作。

### 第 14 章：端到端实战与面试复盘

- **学习目标：** 把服务器、Kubernetes、GPU、网络、存储、调度和训练诊断能力串成完整生产方案。
- **内容大纲：** 新 GPU 节点从验收到入池；提交并运行多节点训练；人为注入调度、网络、存储或 GPU 故障；发现、止损、恢复和验证；复盘和自动化改进；简历项目表达与面试回答结构。
- **实践与产出：** 完成一份端到端运行手册和演练复盘，附架构图、验收记录、排障证据、恢复验证及后续改进项。
- **章末面试题：** 12-15 题；以跨层综合场景和设计题为主，检验候选人能否说明假设、证据、权衡、恢复及沟通。

## 统一写作与交付要求

每章作者按以下顺序组织内容：

1. 学习目标与岗位场景。
2. 先备知识、关键概念和组件边界。
3. 生产实践方法及适用前提。
4. 可复现的实验、检查步骤或案例。
5. 排障流程、风险边界和恢复/回滚方法。
6. 本章产出物和验收标准。
7. 章末面试题及参考答案要点。

内容质量要求：

- 每章至少有一个可验证的实践任务和一个明确产出物；只讲概念不算完成。
- 每章至少包含 3 幅编号技术图，优先表现架构、资源/数据流、决策或排障过程；图中组件关系须与正文和引用来源一致。
- 岗位要求写明“IB 或 RoCEv2”“PyTorch Distributed/MPI/NCCL 至少一类”“存储类型中的两类以上”“Python/Go/Shell/Ansible 自动化能力”的，实践深度按此最低范围设计；其余技术用于理解边界和选型，不要求每位读者在实验中全部部署。
- 命令、配置和 API 示例须说明适用版本/环境、预期结果和失败时的下一步；生产变更须列出影响范围、验证和回滚条件。
- Kubernetes、NVIDIA、NCCL、网络和存储组件发展较快。涉及版本行为、成熟度或推荐配置时，引用对应官方文档并标注核对日期；区分稳定能力、实验能力和厂商特定能力。
- 不编造性能数字、生产案例或兼容性结论。基准值须交代硬件、拓扑、软件版本和测量方法。
- 面试题每章 8-15 题，按概念、场景、排障、设计组织；给出考察点和简明答案要点，避免只考缩写与背诵。
- 术语首次出现时给出中英文全称；全书统一缩写、命令风格、指标单位和故障记录格式。

## 全书验收标准

- 章节顺序从底层基础递进到跨层生产实战，章节之间的先备关系清晰。
- 招聘要求映射表中的每一项都至少对应一个有实践内容的章节。
- 每章均有学习目标、具体大纲、实践产出和章末面试题要求。
- 每章正文至少有 3 幅有效图表，图表能在站点中渲染且没有断链。
- 故障章节能够覆盖“现象 -> 证据 -> 假设 -> 验证 -> 止损/恢复 -> 复盘”的闭环。
- 生产操作都能找到前置条件、风险边界、成功判据和回滚路径。
- 全书的重要版本、兼容性和性能结论均可追溯到来源或实验记录。
